Project summary

I owned Trainix end to end: research, the Figma library, and the React front end, built with an AI coding assistant. The result is one design language that designers, developers and the AI all follow, from colour tokens to the last button state.

But first!

The Problem

A regulated tool needs to show a lot of data without feeling heavy, and we started with no shared language between design and code.

Three sets of names. Figma, the UI kit and the code called the same colour three different things
One-off styles crept in. Without tokens, every new screen risked a new grey, radius or button
Handoff by eye. The developer had to interpret pictures instead of matching names
Dense, regulated screens. Long tables, statuses and audit records that can feel heavy and stressful

Not to forget

The Goals

User

Make a dense, regulated tool feel calm and clear for admins, managers and employees.

Team

Turn handoff into matching names, not reading pictures

Design

One library, every state designed, nothing one-off

Discover

What I studied

I looked at tools people already trust with dense data: Linear, Stripe, Zoho, Deel, Remote, Apollo and Mixpanel. I borrowed their principles, not their look. Trainix kept its own blue, type and tokens.

What they get right

1.

Quiet chrome, loud content: the sidebar fades into the page so the data does the talking

2.

Restraint with colour: brand blue only for the main action, links and focus; red only for errors

3.

Calm tables: no zebra stripes or vertical lines, the person first, one place for row actions

4.

Soft status badges: a dot and a word on a pale tint, never colour alone

5.

Every state designed: skeletons while loading, an action when empty, a retry on error

Everything that shaped the system

What the research changed

Teams trust tools that stay calm under a lot of data

Designers and developers argue less when they share the same words

A component library without written rules drifts within weeks

An AI coding assistant needs explicit rules, or it invents new styles

Status shown only by red and green fails people with colour blindness

Empty, loading and error moments are where enterprise tools lose trust

Key decisions

Figma names are code names

bg-brand-solid in Figma is bg-brand-solid in Tailwind. Handoff became matching words, not reading pixels.

Two tiers of tokens

Raw primitives like blue/700 feed 51 semantic tokens named by their job. Components only ever use the semantic ones.

Restyle a proven kit

Untitled UI React gave accessible behaviour through React Aria. I rebuilt its look to match my Figma library instead of starting from zero.

Smaller calls that mattered: skeletons for content and spinners only inside buttons · errors appear when you leave a field and clear the moment it is fixed · buttons say exactly what they do (Create, Assign, Approve), never Submit.

Accessibility

The system runs a WCAG contrast audit on every token change. It flagged three real issues in the Trainix colours, each with a one-step fix.

Warning text · 3.56:1

Orange warning text on white sat below the 4.5:1 needed for small text. Fix: map it one shade darker.

Warning badge · about 3.3:1

Orange on its pale tint failed too. The audit suggests the smallest change that passes.

Error badge · about 4.0:1

Red on its pink tint was close but under AA. One step darker passes, with no change to the look.

Also built in: visible focus rings on keyboard focus, labelled inputs, status always shown with a word, reduced-motion support, and a colour-vision simulator.

Results

Counted from the system itself, not projections:

20 components

Every state drawn in Figma and built in code: 14 stable, 2 in code only, 4 in progress, each labelled honestly.

51 semantic tokens

Every colour in the product named by its job, tied to one primitive palette, the same in Figma and code.

13 principles · 8 AI rules

Written down with a Do and a Don’t each, so designers, developers and the AI build the same way.

Key takeaways

Names are the real handoff. Once Figma and code share words, a review becomes “does it match?” instead of “what did you mean?”

Design the boring states first. Loading, empty and error screens are where trust is won or lost in a compliance tool.

Let the system check itself. Live contrast checks caught issues my eyes had already accepted.

Rules scale better than reviews. Writing them for an AI assistant made them clearer for people too.

Looking Forward

Trainix shows how I work on complex products: research first, principles written down, and a system that designers, developers and an AI assistant can all follow. In a compliance tool, calm is a feature.
